# Phase 7: uat-conversation — Discussion Log

Discussed phase 7 (uat-conversation) with the user. Established the architectural constraint: gsd_execute is a tool invoked by the driving agent and cannot block on an inline human answer (the ask_user_question primitive lives at the driving-agent level), so the conversational UAT loop is a two-turn marker->handoff. The executor already stops at checkpoint:decision / checkpoint:human-action and returns structured state (phase 4); phase 4's D-07 explicitly deferred this conversation. User chose: (1) marker->driving-agent handoff (gsd_execute returns an 'awaiting human decision' marker; driving agent asks via ask_user_question then re-invokes), no inline prompt; (2) answer passed as gsd_execute input (answer + decision_id args) AND persisted into the CHECKPOINT-<PP> frontmatter so a context-reset resume carries it; (3) no-answer re-invocation returns the marker again without re-executing, stale answers are ignored, and human-verify/decision/human-action all share one stop+await path.
