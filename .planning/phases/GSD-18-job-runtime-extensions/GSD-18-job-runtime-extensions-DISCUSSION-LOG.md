# Phase 18: job-runtime-extensions — Discussion Log

Discussed phase 18 (job-runtime-extensions) with the user. Grounded in the Phase 9 runtime (lib/jobs.js, job-wrapper.mjs, _runner.js), the manifest accessors, the tool-registration pattern, and the host subagents service contract. Key grey area surfaced: subagent runs are in-process and bound to exec.signal, so they cannot OS-detach like the shell jobs. User chose: (1) in-process detached subagent launched WITHOUT exec.signal, reporting via the shared result file (JOBX-01); (2) per-job timeout default 60s (config jobs.timeout) marking failed 'timeout' (JOBX-02); (3) cancellation as gsd_job action=cancel marking failed 'cancelled' (JOBX-02); (4) a single gsd_job tool with action launch|status|cancel|retry and kind shell|subagent (JOBX-03); (5) manual retry + a real FIFO scheduler with concurrency 2 (config jobs.concurrency) (JOBX-04). Follow-up edge decisions: terminal outcomes keep status done|failed with a structured reason field; subagent results reuse the existing result-file shape; scheduler concurrency default 2 configurable. Preserved the Phase 9 no-throw invariant (missing/corrupt result = still running; gsd_job never throws over a bad manifest).
